# Fixture: the same PioneerRx "Rx Transaction Details By Submission Type (BETA)" report, run over a
# range rather than a day — which is the shape of the twelve-month history the pharmacy is asking
# PioneerRx for, and the shape nothing has ever been tested against.
#
# Every prescription number and group number is invented. BINs, PCNs, NDCs and money follow the
# real report's formatting exactly, because the reader's positions are fixed from the file and its
# whole job is to refuse a row that does not fit the shape.
#
# What this file carries that the daily one cannot:
#   - two months in one file, 30 September and 1 October, so a month boundary is crossed inside a
#     single payer's section;
#   - a page break in the middle: the stray "20" and "1f" fragments the printer leaves on their own
#     line, followed by the title block and column header repeated as page two begins;
#   - the same day's rows appearing twice — 30 September is printed once under each of two payers,
#     which is what a re-sent day looks like to the importer;
#   - two identical transactions on one day (same prescription, fill, status, date, BIN, NDC and
#     money), which is the only case where the reader has to invent a suffix to tell two rows apart;
#   - a row with a status the reader does not recognise, so the skip reasons can be asserted rather
#     than assumed.
